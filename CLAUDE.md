# Контекст проекта для Claude

## Кто и зачем

Дарья участвует в хакатоне Школы 21 (7–9 ноября 2026), кейс ОНСОФТ «ИИ, который не обманывает».
Команда: Дарья (не программист, работает через Claude) и подруга-дизайнер (подключится 8 ноября).
Цель — первое место. Защита 9 ноября: 5 минут доклад + 3 минуты вопросов с живой проверкой системы.
Отвечай Дарье по-русски, простыми словами, без жаргона.

## Кейс в двух словах

По документам госзакупки (папки `packages/P01..P06`, 4–5 txt-файлов) отвечать на вопросы (`questions.csv`).
Формат сдачи: `answers.csv` (`id;status;answer;quote;file`), статусы: `ответ`, `расхождение`, `нет в документах`, `не знаю`.
Оценщик `data/train/check.py`: **индекс доверия = (верно − обман) / всего × 100**. «Не знаю» = 0, обман = −1.
Обман: неверное значение, цитаты нет в документах дословно (после нормализации), ответ на то, чего нет,
«нет в документах», когда ответ есть, пропущенное или ложное расхождение.
Ловушки: ответа нет; «требования нет» (ответ «нет, не установлено»); значение изменено в `05_izmeneniya`;
извещение и контракт противоречат друг другу (`расхождение`, оба числа в answer). В check.py есть тип «пустой файл».

В день защиты дадут новый набор (~100 вопросов того же вида, новые закупки) **без ответов**.
Прогон без правок кода и промптов: `run.bat solve --data data/control` → `results/control/answers.csv`.

Критерии (из 100): индекс на контрольном наборе 30; честный замер было/стало на одной модели и разбор типов обмана 25;
проверки (что ловит, работает ли на ловушках) 15; понятность дашборда для не-ИТ 15; воспроизводимость
(запуск по инструкции, модель и промпты описаны, ключей нет) 10; уровень со звёздочкой (агентный цикл, узкие критики
с замером вклада каждого, трудные файлы) 5. Жюри спросит: «Покажите обман, который поймала система, и как».

## Архитектура (готово)

- `src/trustai/docs.py`: чтение (BOM, utf-16, cp1251/koi8), пустые файлы, разбиение на предложения с id `S1..`,
  вырезание спрятанных инструкций для ИИ, разбор изменений извещения (старая/новая редакция).
  `Package.quote_in_docs()` проверяет цитату **ровно как check.py** (его декодирование и `norm`).
- `retrieval.py`: BM25 по основам слов + словарь синонимов закупок; топ-12 + по 3 из каждого файла + весь файл изменений.
  Покрытие золотых цитат на train: 61/61, ~1.7 тыс. символов контекста на вопрос.
- `llm.py`: GigaChat (OAuth, авто-скачивание сертификата Минцифры в `certs/`) и OpenAI-совместимый провайдер.
  Кэш ответов `results/cache/` (повторные прогоны бесплатны), журнал `results/journal.jsonl` (без ключей).
- `checks.py` — критики: цитаты (с починкой по id фрагмента), числа + единицы (руб/%/дни/месяцы; номера пунктов «2.1.»
  не считаются числами), расчёт кодом (`calc`-выражение от модели, безопасный eval), изменения извещения,
  расхождения (+ подтверждение вторым запросом), да/нет и отрицания.
- `pipeline.py`: агентный цикл. Модель → JSON с `mentions` (sid, file, quote, value), `status`, `answer`, `calc` →
  проверки → замечания модели (до `max_retries`) → иначе «не знаю». «Нет в документах» перепроверяется по полному тексту.
  Опционально ИИ-критик. Флаги в `configs/*.json`.
- `configs/00..10`: лестница «было → стало» (каждый шаг добавляет одну проверку). `final.json` = итоговая система.
- `runner.py`, `run.py`: команды `check`, `ask`, `solve`, `ladder`, `report`. `.bat`-обёртки для Windows.
- `report.py` → `results/report.html` (дашборд). `app/server.py` + `index.html` → живое демо на :8501.
- `tests/`: 12 автотестов критиков на реальных документах; `tests/make_hard.py` → `data/hard/H01` (трудные файлы).
- Только стандартная библиотека Python (у Дарьи Python 3.15 на Windows, pip-пакеты не нужны).

## Правила

- Решатель **никогда** не читает `answers_public.json` (только оценщик и дашборд). Не подгонять ответы руками:
  за ручную правку результата — 0 по главному критерию.
- Ключи только в `.env` (в .gitignore). Не печатать ключ в логах и не класть в код.
- Не переобучаться на train: правила и синонимы должны быть общими для «вопросов того же вида».
  Для честной оценки обобщения держать отложенную закупку (например, настраивать на P01–P04, проверять на P05–P06).
- «Было» и «стало» — на одной модели (`GIGACHAT_MODEL`), менять модель между шагами нельзя.

## Модель

Основная: **модель организатора ОНСОФТ** — Qwen 3.8 27B, OpenAI-совместимый API `https://ai.on-soft.ru/v1`,
модель `qwen3-6-practice`, окно 128k, умеет рассуждать (`<think>…</think>` вырезается в `llm.py::strip_reasoning`).
Ключ командный, действует до 10.11.2026 12:00 МСК (защита 9.11 — успеваем). В `.env`: `LLM_PROVIDER=openai`, `OPENAI_*`.
Лимиты ключа: 2 параллельных запроса, 40 запросов/мин, 600 тыс. токенов/мин, 40 млн токенов/сутки.
При 429 код ждёт и повторяет. По правилам ОНСОФТ нельзя отправлять в модель содержимое `.env`, пароли, ПДн.
Запасная: GigaChat-2-Max (`LLM_PROVIDER=gigachat`, связь проверена 7.11, сертификат Минцифры в `certs/`).
Сравнение «было/стало» — строго на одной модели. Стоит попробовать `OPENAI_EXTRA_BODY` с `enable_thinking: false`
и сравнить замером (скорость против точности). При 40 запросах/мин можно добавить 2 параллельных потока в runner.
