# ИИ, который не обманывает

Кейс ОНСОФТ, хакатон Школы 21 (7–9 ноября 2026).

Система отвечает на вопросы по документам госзакупки и **не выдумывает**: каждый ответ подтверждается
дословной цитатой, а набор проверок-«критиков» (обычный код) ловит обман. Если ответ не удалось подтвердить,
система честно отвечает «не знаю».

## Как это работает

```
вопрос ─► поиск нужных кусков документа ─► модель отвечает + цитаты
                                              │
                    ┌─────────────────────────┘
                    ▼
           проверки кодом (критики)
           1. цитата дословно есть в документе
           2. число из ответа есть в цитате, с нужной единицей (руб., %, дни, месяцы)
           3. расчёты (проценты, суммы) делает код, а не модель
           4. значение не из старой редакции (изменения извещения)
           5. разные значения в разных документах → «расхождение»
           6. «да/нет» не противоречит словам «не установлено», «не требуется»
           7. «нет в документах» перепроверяется по полному тексту
                    │
         все прошли? ── да ──► ответ
                    │
                   нет ──► замечание модели и новая попытка (до 2 раз) ──► иначе «не знаю»
```

## Модель

Основная — модель организатора ОНСОФТ: **Qwen 3.8 27B** (`qwen3-6-practice`, OpenAI-совместимый API
`https://ai.on-soft.ru/v1`), режим рассуждений включён, температура 0.1. «Было» и «стало» меряются на ней же.
Если модель рассуждала так долго, что не успела дать ответ, система повторяет этот запрос без рассуждений.
Запасная — GigaChat-2-Max (`LLM_PROVIDER=gigachat`).

## Результаты (официальный check.py, одна и та же модель)

| Набор | Вопросов | Было: модель «как есть» | Стало: итоговая система |
|---|---|---|---|
| Учебный набор организатора (на нём разбирали ошибки) | 71 | 94.4 (2 обмана) | **100.0 (0 обманов)** |
| Те же закупки, вопросы переформулированы (`data/paraphrase`) | 71 | 94.4 (2 обмана) | **100.0 (0 обманов)** |
| Трудные файлы (`data/hard`: cp1251, пустой файл, инструкция для ИИ, огромный документ) | 13 | 100.0 | **100.0** |

Режим модели (та же модель, меняется только «рассуждать перед ответом»; `OPENAI_EXTRA_BODY` в `.env`):

| Режим | Учебный набор: было → стало | Другие формулировки: было → стало | Секунд модели на вопрос |
|---|---|---|---|
| с рассуждениями (итоговый) | 94.4 → **100** | 94.4 → **100** | ≈23 |
| без рассуждений | 77.5 → **100** | 77.5 → **100** | ≈4 |

Без рассуждений модель обманывает в 4 раза чаще (8 обманов против 2), но проверки ловят всё, и система
работает в 6 раз быстрее. Итоговым оставлен режим с рассуждениями: у самой модели меньше ошибок, значит больше
запас на новых закупках. Быстрый режим — запасной, если в день защиты сервер будет перегружен.

Пошаговый замер — `results/ladder.json`, вклад каждой проверки (выключаем по одной) — `results/loo_*.json`,
всё вместе — дашборд `results/report.html`.

Что выяснили замером:
- Без проверок модель обманывает в основном цитатами: пересказывает документ своими словами или склеивает куски,
  и такой «цитаты» в документе нет. Проверка цитат кодом + подстановка точного текста фрагмента это устраняет.
- Расчёты (обеспечение = цена × процент) модель пишет формулой, а считает код.
- На переформулированных вопросах модель трижды ответила «нет в документах», хотя ответ был; перепроверка по
  полному тексту это поймала и исправила.
- Вклад проверок (выключаем по одной из итоговой системы, `run.bat loo`), на переформулированных вопросах:
  без проверки цитат −14.1 балла (5 обманов), без расчёта кодом −11.3, без перепроверки «нет в документах» −8.5
  (3 обмана), без цикла исправлений −4.2, без поиска нужных кусков −1.4. Критики изменений, расхождений и «да/нет»
  на этих вопросах не понадобились (модель там не ошибалась) — они страхуют от ловушек на новых данных.
- Без рассуждений нашлись ещё два вида обмана, на них добавлены проверки: «гарантийный срок не установлен» со ссылкой
  на чужой параметр («обеспечение гарантийных обязательств не требуется») — ловит узкий критик отрицаний (второй
  запрос только для ответов «требования нет»); модель повторяла «нет в документах», даже когда перепроверка нашла
  ответ, — теперь это не принимается: найденный фрагмент проходит все проверки, иначе «не знаю».
- ИИ-критик (второй запрос «проверь ответ») не улучшил результат, а запросов стало на 70% больше; в первой
  версии он видел только одну цитату и браковал верные расчёты (индекс падал до 87.3). В итоговой системе выключен.

## Установка (Windows)

1. Python 3.10+ с python.org (галочка «Add python.exe to PATH»).
2. В папке проекта дважды кликнуть `setup.bat`. Он создаст окружение `.venv`, файл `.env` и прогонит автотесты.
3. Открыть `.env` в Блокноте и вписать ключ модели (`OPENAI_API_KEY` для модели ОНСОФТ или `GIGACHAT_AUTH_KEY`).
   Ключ хранится только в `.env`, в коде и git его нет.

Всё работает на чистом Python без сторонних библиотек: ничего не нужно ставить через pip.

## Запуск

| Команда | Что делает |
|---|---|
| `run.bat check` | проверить связь с моделью |
| `run.bat ask P01 "Какой срок выполнения работ?"` | задать один вопрос и увидеть все проверки |
| `run.bat solve` | прогнать вопросы учебного набора (конфиг `configs/final.json`) |
| `run.bat solve --data data/control` | **контрольный набор**, результат: `results/control/answers.csv` |
| `run.bat ladder` | замер «было → стало» по шагам `configs/00…10` |
| `run.bat loo` | вклад каждой проверки: выключаем по одной из итоговой системы (`--data data/paraphrase` — на переформулировках) |
| `run.bat report` | дашборд `results/report.html` |
| `app.bat` | веб-интерфейс для живой демонстрации (http://127.0.0.1:8501) |
| `python tests/make_hard.py` | собрать закупку H01 с трудными файлами (кодировка, пустой файл, инструкция для ИИ, огромный документ) |
| `python tests/make_paraphrase.py` | собрать набор `data/paraphrase`: те же закупки, вопросы другими словами (проверка обобщения) |

На macOS/Linux вместо `run.bat` — `python run.py`.

Запросы идут в 2 потока (лимит ключа ОНСОФТ; `LLM_WORKERS=1` — по одному). Если связь с моделью оборвалась,
вопрос не превращается молча в «не знаю»: после прогона такие вопросы автоматически переспрашиваются (до 3 кругов).
Ответы модели кэшируются в `results/cache/`, поэтому повторный прогон бесплатный и даёт тот же результат.

### Контрольный набор в день защиты

Режим — с рассуждениями (как в `.env.example`). При 2 потоках 100 вопросов ≈ 15–20 минут.

1. Положить папку `packages/` и `questions.csv` в `data/control/`.
2. `run.bat solve --data data/control`
3. Сдать `results/control/answers.csv`.

## Структура

```
src/trustai/
  docs.py        чтение документов: кодировки, пустые файлы, вырезание спрятанных инструкций
  retrieval.py   поиск нужных предложений (BM25 + словарь синонимов закупок)
  llm.py         подключение к модели (GigaChat / OpenAI-совместимый), кэш, журнал запросов
  checks.py      проверки-критики
  pipeline.py    агентный цикл
  runner.py      прогон набора и замер официальным check.py
  report.py      дашборд «было/стало» (results/report.html)
prompts/         все промпты (тексты инструкций модели)
configs/         шаги эксперимента «было → стало», final.json — итоговая система
data/train/      учебный набор организатора
data/hard/       закупка H01 с трудными файлами (уровень со звёздочкой)
data/control/    сюда кладётся контрольный набор
app/             веб-интерфейс (server.py + index.html), без сторонних библиотек
results/         ответы, журнал запросов (journal.jsonl), статистика, дашборд
tests/           автотесты проверок на настоящих документах
```

## Честность замера

- «Было» и «стало» меряются на одной модели и одним и тем же `check.py` организатора.
- Система **не читает** `answers_public.json`: правильные ответы использует только оценщик.
- Все запросы к модели пишутся в `results/journal.jsonl` (время, модель, токены), ключи туда не попадают.

## Сертификат Минцифры

Если `run.bat check` пишет `CERTIFICATE_VERIFY_FAILED`, скачайте корневой сертификат Минцифры
(gosuslugi.ru/crt, файл `russian_trusted_root_ca.cer`), положите в папку `certs/` и раскомментируйте в `.env`
строку `GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca.cer`.
